# NeuroScan AI — Federated Brain Tumor Detection

A GitHub-ready research prototype for **binary brain MRI classification (Tumor vs No Tumor)** using **VGG16 transfer learning**, **3 simulated hospital clients**, **sample-weighted FedAvg**, **Grad-CAM**, and a Flask inference demo.

> **Important:** This repository is an academic/research prototype. It is **not a medical device and must not be used for clinical diagnosis, treatment decisions, or emergency care.**

## Project overview

The included Google Colab notebook trains one global brain-tumor classifier without directly pooling the simulated hospitals' training process into a single client. Each federated round sends the current global weights to three local models, trains each model on its hospital dataset, and combines their weights with sample-weighted Federated Averaging (FedAvg).

The notebook also performs an 80/10/10 train/validation/test split per hospital, exact cross-hospital duplicate removal, global and per-hospital evaluation, ROC-AUC analysis, confusion matrix generation, Grad-CAM visualization, model saving, and export of JSON/CSV artifacts.

## Datasets used by the notebook

| Client | Kaggle dataset |
|---|---|
| Hospital 1 | `masoudnickparvar/brain-tumor-mri-dataset` |
| Hospital 2 | `ahmedhamada0/brain-tumor-detection` (Br35H) |
| Hospital 3 | `navoneel/brain-mri-images-for-brain-tumor-detection` |

The notebook converts available source labels into the binary classes `no_tumor` and `tumor`. Dataset files are intentionally **not included** in this repository.

### Neural network

```text
MRI 224x224x3
   -> VGG16 (ImageNet, include_top=False, frozen)
   -> GlobalAveragePooling2D
   -> Dense(256, ReLU)
   -> Dense(128, ReLU)
   -> Dense(1, Sigmoid)
   -> Tumor probability
```

Notebook defaults: 5 federated rounds, 1 local epoch/client/round, batch size 16, Adam at `1e-4`, binary cross-entropy, and horizontal flip/rotation/zoom augmentation.

## Quick start — training in Google Colab

1. Open `notebooks/NeuroScan_AI_Federated_Colab.ipynb` in Google Colab.
2. Select a GPU runtime if available.
3. Run the cells in order.
4. KaggleHub downloads all three datasets.
5. The notebook standardizes the datasets and trains the federated VGG16 model.
6. After training, the notebook writes:
   - `/content/models/neuroscan_fedavg_vgg16.keras`
   - `/content/artifacts/metrics.json`
   - `/content/artifacts/federated_history.csv`
   - `/content/artifacts/hospital_results.csv`
7. It can also copy those files to `MyDrive/NeuroScan_AI/`.

Do not commit Kaggle datasets or patient/medical data to GitHub.

## Run the web demo locally

Create and activate a Python environment, then install dependencies:

```bash
pip install -r requirements.txt
```

Copy the trained model generated by Colab to:

```text
models/neuroscan_fedavg_vgg16.keras
```

Start the app:

```bash
python run_app.py
```

Open the local address printed by Flask. Upload a JPG/JPEG/PNG MRI image. The demo returns the predicted class, confidence, tumor probability, and a Grad-CAM overlay.

The web demo does **not** retrain the model. It only loads the saved global model.

## Federated-learning note

This project **simulates** three federated clients inside one Colab runtime. It demonstrates the FedAvg training logic, but it is not a production cross-institution federated network. A real deployment would require secure client/server orchestration, identity and access controls, encryption, audit logging, governance, privacy review, and institution-specific validation.

## Grad-CAM

The notebook and inference module use VGG16 layer `block5_conv3` to generate a heatmap showing image regions that contributed to the prediction. A Grad-CAM image is an explanation aid, **not a tumor segmentation mask** and not proof of tumor location.

## Reproducibility

The notebook sets Python, NumPy, and TensorFlow random seeds to `42`. Exact results can still vary across hardware, TensorFlow/CUDA versions, dataset revisions, and nondeterministic GPU operations.

## Security and privacy

Never commit API keys, passwords, Kaggle credentials, patient identifiers, raw clinical scans, or protected health information. The provided demo uses local uploads and should not be exposed as a clinical service without a proper security and regulatory design.
